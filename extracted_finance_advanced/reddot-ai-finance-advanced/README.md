# Advanced AI for Finance Professionals — Developer Handoff

A self-contained, browser-based course platform for Red Dot Technologies Pvt. Ltd.
Twelve modules, ~10.5 hours of content, assessments, a paywall, and a completion certificate.

**The finished product is a single HTML file.** No server, no database, no npm packages,
no build tooling beyond Node.js. Upload one file and it works.

---

## 1. Quick start

```bash
node build.js
```

Output: `dist/advanced-ai-for-finance-professionals.html`

Open that file in any browser to test. To publish, upload it to the web server
(see *Deployment* below). Nothing else needs to be uploaded.

**Requirements:** Node.js (any recent version). No `npm install` required.

## 3. Where to change what

### Layout, colours, spacing, typography → `src/styles.css`
All design lives here. The palette is defined once at the top under `:root`:

```css
--navy   #0F1E3D    /* primary dark */
--red    #C8102E    /* Red Dot brand red */
--gold   #B8892B    /* accent, certificate, premium cues */
--line   #DFE6F0    /* borders */
```

Change a variable there and it updates everywhere. Key blocks are commented:
`/* hero */`, `/* lesson */`, `/* quiz */`, `/* paywall */`, `/* lead + certificate */`.

Responsive breakpoints are at the bottom (`@media(max-width:940px)`), plus a
`@media print` block that formats the certificate for printing.

### Home screen / screen layout → `src/app.js`
Each screen is a function returning an HTML string:

| Function | Screen |
|---|---|
| `homeView()` | **Home / programme overview** — hero, feature cards, curriculum, audience |
| `homeModList()` | The curriculum list on the home screen |
| `lessonView()` | A module page |
| `quizPageView()` | An assessment page |
| `paywallView()` | The payment screen |
| `certView()` / `leadFormView()` | Certificate and the details form before it |
| `sourcesView()` | Sources & further reading |
| `renderNav()` | Left sidebar |
| `ctaBand()` | The PECP call-to-action block |
| `footer()` | Page footer |

`go(view)` is the router. It also enforces the paywall — see *Paywall* below.

### Prices, contacts, preview → `src/config.js`

```js
const PRICE  = { amount:"2,499", was:"3,999", currency:"NPR", intro:true };
const FREE_PREVIEW = ["a1"];      // module ids readable without payment
const CONTACT = { email:"...", phone:"..." };
const LEAD_ENDPOINT = "";         // paste your Google Apps Script URL here
```

To make two modules free: `FREE_PREVIEW = ["a1","a2"]`.
To remove the "was" price: set `was:""`.

### Course content → `src/course-data.js`
One object per module:

```js
{
  id:"m3", tag:"Module 3", time:"50 min",
  title:"...", summary:"...",
  objectives:[ ... ],
  sections:[ { h:"Heading", html:"<p>Body HTML…</p>" }, ... ],
  practitioner:{ title:"…", text:"…" },
  activity:{ title:"…", text:"…" },
  takeaways:[ ... ],
  quiz:[ { q:"…", opts:["…","…","…","…"], a:2, fb:"Explanation shown after answering" } ]
}
```

⚠️ **`a` is the zero-based index of the correct option.** If you reorder `opts`,
update `a` to match. Correct answers are currently distributed evenly across all
four positions — please keep it that way so the assessment stays meaningful.

The total duration shown on screen is calculated automatically from the `time`
fields, so update those if you add or remove content.

### Diagrams
Each module has an inline SVG diagram generated by `FIG.a1()` … `FIG.a12()` in
`app.js`, with captions in `FIGCAP`. They are plain SVG strings — edit or replace
freely. They are drawn light-on-dark because they sit on a navy panel (`.figure`).

## 4. The paywall — how it works and what it is not

Module 1 is a free preview. Modules 2–12, all assessments and the certificate
require access.

1. The buyer pays via the Fonepay QR on the payment screen.
2. They submit name / email / institution / transaction reference — this posts to
   `LEAD_ENDPOINT` so Red Dot can verify the payment.
3. Red Dot verifies the payment, generates a code in
   `tools/access-code-generator.html`, and emails it to the buyer.
4. The buyer enters the code and the course unlocks. Unlock persists in that
   browser via `localStorage`.

Codes are validated offline by checksum — no server call is needed.

> ### ⚠️ Security limitation — please read
> This is a **static file**, so the paywall is a *deterrent*, not enforcement.
> Anyone comfortable with browser developer tools can bypass it. That is an
> accepted trade-off at this price point. If real enforcement is needed later,
> the course must sit behind a server-side login that serves module content only
> to authenticated, paid users.

### `CODE_SALT` must stay in sync
`src/config.js` and `tools/access-code-generator.html` both contain:

```js
const CODE_SALT = "RDT-AIFA-2026";
```

**If you change one, change both**, or previously issued codes stop working.
Changing the salt invalidates every code already issued — useful if codes leak,
but existing customers will need reissued codes.

`tools/access-code-generator.html` is **internal**. Do not upload it to the website.

## 5. Collecting registrations

Set `LEAD_ENDPOINT` in `src/config.js` to a Google Apps Script Web App URL
(or any endpoint accepting a POST). Two payload types are sent:

- `type:"ACCESS_REQUEST"` — buyer submitted payment details, awaiting a code
- certificate details — name, email, institution, designation, department

Posts use `mode:"no-cors"` with `Content-Type: text/plain`, which avoids a CORS
preflight against Apps Script. The response is intentionally not read. If
`LEAD_ENDPOINT` is empty, data is kept only in the visitor's browser.

## 6. Deployment

1. Run `node build.js`.
2. Upload `dist/advanced-ai-for-finance-professionals.html` to the web server, e.g. as
   `reddottech.com.np/ai-for-financial-professionals/index.html`.
3. Link to it from the main site navigation.

The file is ~640 KB, mostly the embedded logos. To reduce size, re-export the
PNGs in `assets/` at a smaller resolution and rebuild.

**Caching note:** browsers cache aggressively. After republishing, hard-refresh
(Ctrl/Cmd + Shift + R) when testing, or add a version query string to the link.

## 7. Testing checklist before publishing

- [ ] **Scan the Fonepay QR with a phone** and confirm it resolves to Red Dot's account
- [ ] Module 1 opens without payment; Module 2 shows the paywall
- [ ] Generate a code in the tool → it unlocks the course
- [ ] Complete all 12 assessments → certificate unlocks
- [ ] Certificate prints correctly (Ctrl/Cmd + P)
- [ ] Check on a phone — sidebar opens via the ☰ button
- [ ] Submit a test payment request and confirm it reaches your sheet
- [ ] Progress persists after closing and reopening the browser

To reset progress while testing, run in the browser console:

```js
localStorage.removeItem('aiFinAdv_v1'); location.reload();
```

## 9. Relationship to the foundational programme

This is **Level 2**. It assumes learners have completed *AI for Financial Professionals*
(the `reddot-ai-finance` project) or hold equivalent working knowledge, and the hero
section states this prerequisite explicitly.

The two courses are deliberately **independent** in the access-code system:

| Course | Salt | Certificate prefix | localStorage key |
|---|---|---|---|
| AI for Financial Professionals | `RDT-AIFP-2026` | `RDT-AIFP-` | `aiFinPro_v1` |
| Advanced AI for Finance Professionals | `RDT-AIFA-2026` | `RDT-AIFA-` | `aiFinAdv_v1` |
| AI for Healthcare Professionals | `RDT-AIHP-2026` | `RDT-AIHP-` | `aiHealthPro_v1` |

A code issued for one course will **not** unlock another. Use the generator in this
project's `tools/` folder for this course only.
